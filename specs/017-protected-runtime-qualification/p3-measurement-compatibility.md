# P05 measurement transaction compatibility finding

Status: isolated eligibility finding; amendment recommendation only.
Scope: existing feature017 T013P05, first codeXfactory pilot.

## Commission and unchanged boundary

Brett explicitly commissioned "Implement and test T013P05 in isolation" using
[p3-measurement-plan.md](p3-measurement-plan.md) after its six local preparation
gates passed at `9be62f196694103b6735df9237f511a87b20b10f`. Its eligibility rule
requires a governed factory/adapter amendment before dependent code when accepted
interfaces cannot provide authenticated transaction correlation. No source
acceptance or operation is inferred from this implementation commission.

## Observed isolated results

Four external eligibility probes pass in a disposable network-none, read-only
source container. The test process has only loopback, no supplementary groups,
no capabilities and no privilege regain; its home/scratch is private. It uses
actual Linux process/file measurement, real local TLS and independently pinned
client/server certificates. Provider/authority selections remain explicit fixtures.

| Probe | Observation | Limit |
| --- | --- | --- |
| Complete canonical body | 8,860 bytes including 5,247-byte configuration and 2,870-byte policy; exact accepted root fields | Fits 16,384 bytes for this fixture only |
| Independent byte derivation | Approved root paths/artifact digests and actual PID/start reconstruct the composition and complete policy commitment | Local feasibility, not manager/remote-finalization qualification |
| Allowed/denied peer | Selected pinned mTLS request succeeds; a distinct valid worker certificate receives explicit 403 | Service availability established; deployed custody/issuance unqualified |
| Transport/client compatibility | Distinct requests and an intentionally wrong nonce response header all yield the same direct status/body; old observation client refuses direct P05 response and unlisted measurement operation | Existing APIs do not supply the required explicit correlation capability |

The transport probe demonstrates an interface gap, not a claim that TLS is
unauthenticated or that every purpose-built transport is impossible. A live
unchanged target can legitimately produce identical measurement bytes. The
missing property is independently checkable binding of those bytes to the
selected fresh request under the accepted source contract. A timestamp alone
cannot provide it, and a service that echoes a fresh nonce while reusing stale
facts must still be excluded by actual local remeasurement and late scope checks.

The first fixture-import attempt failed before tests; the corrected four-case
run has zero failures/errors/skips. An in-bench unshare attempt was refused by
the container and started no tests. Neither diagnostic is counted as success.
The actual disposable namespace is absent; independent audit covers 11 recorded
process generations with zero live processes, and both exact scratch roots are
removed. Redacted size/gap, JUnit and cleanup receipts remain in local QA records;
no raw configuration/policy, key, token, browser state or factor is retained there.

## Why existing source cannot simply be repurposed

The accepted [factory boundary](https://github.com/opensoft/openXfactory/blob/c2dfbbcc6fa6965fcde18661bddca1dac7128d47/openspec/changes/add-protected-runtime-azure-composition/supporting-docs/composition-boundary.md)
requires the direct `openxfactory-azure-local-measurement-internal-v1` body with
exact fields, complete canonical documents and no extra wrapper. It contains no
request nonce. [PrivateHttps/Response](../../scripts/workload_factory_binding_runtime/hosted/private_http.py)
authenticate the selected TLS peer but return only status/body and discard
response headers. [ObservationClient](../../scripts/workload_factory_binding_runtime/hosted/readback.py)
checks a nonce in its own different closed wrapper and fixed operation allowlist.
It cannot be used for a new P05 operation or direct body without changing those
accepted contracts. Appending a nonce to v1, nesting the direct body in that old
wrapper, reusing invocation_ref or changing the shared client's allowed operations
would silently change the source decision.

## Concrete recommended amendment

Prepare a narrowly governed factory-owned direct measurement profile
`openxfactory-azure-local-measurement-internal-v2`. Keep v1 and all predecessor
profiles immutable. The proposed v2 response has exactly v1's fields plus
`request_nonce`, a 64-character lowercase hexadecimal value generated by the
selected control capability before one authenticated measurement request.
The selected service binds the nonce to its authenticated peer, effective role,
source/incarnation and full case/plan/run/attempt/deployment scope; consumes the
attempt before actual local measurement; and returns the same nonce with the
complete measured bytes. The client checks exact nonce equality and all original
scope/expiry/peer facts before creating a private verified capability. A copied
snapshot cannot be accepted as a response from another selected transaction.

This is a candidate contract decision, not implemented or accepted behavior.
The direct complete response including nonce still fits the original 16 KiB cap;
no secondary body fetch, wrapper, paging, signature vocabulary or extra budget
is proposed. A dedicated P05 client may use unchanged PrivateHttps transport,
without adding operations to ObservationClient. Independent observers still
remeasure real local facts, and control authority still derives complete expected
bytes from independently approved roots/templates. Matching nonces do not replace
freshness, local manager/namespace proof, independent observers or current authority.
P06 actual enrollment remains separate. Existing seven runtime/eight source roles,
three inputs, full/static/report profiles, default refusal, original phase read
accounting/deadlines and source/human/consumer gates remain unchanged.

Factory owns the governance delta; this feature's existing T013P05 remains the
sole implementation row. No new feature or parallel implementation list is
needed. Exact paired review/source acceptance of that amendment must precede
dependent v2 runtime code. Additional local-manager and complete remote budget
eligibility remains unproven; the four probes do not complete P05.

Setup/dispatch unauthorized; feedback deferred; historical blocked writes unreplayed.
