## Source realization

The opt-in Python package `scripts/workload_factory_binding_runtime/hosted/`
implements static-v2 templates, read-only plan admission, actual controlled Linux
generation measurement and independent complete-byte final acceptance. No listener,
CLI flag, broker dispatch path, issuer, process start, cleanup writer or default
activation is added. Existing v1 readers/default refusal and neutral APIs/pins stay
unchanged. Finalization returns internal bytes and a bound record, never proof
readiness or an operational grant. `admit_finalized` explicitly invokes unchanged
full workflow admission, including its independently approved configuration,
operation grant and final lifecycle checks.

A plan exists before any run/process projection. Its closed configuration template
omits only launch.run_id, launch.run_attempt, composition_digest and
authority.policy_digest. The policy template omits only composition_digest. Root-
relative measurement paths and exact executable/artifact hashes, non-root UID,
empty capabilities, host/incarnation/boot/launch and cleanup scope are static.
Staging acknowledgements are snapshotted canonically before further I/O so reused
mutable callback data cannot hide generation drift. No dummy hash, generic patch,
predicted PID or mutable whole-object omission is
used. Actual argv/cwd/executable, PID/start, boot, UID/capabilities and file bytes
are measured before canonical composition -> policy -> configuration derivation.

A signature-valid preflight identity can obtain only the approved existing
environment and plan/case/run/source expiry. Current consumed-scope/source-hold/
protection/scheduler facts are read independently and rechecked after protection
I/O. Wrong phase, audience, source, rerun, missing facts or protection refuse
without starting a process or reaching issuance/custody/full admission.

Protected finalization requires current identity and acknowledged generation-bound
staging cleanup through trusted read-only capabilities. A separate authority uses
its own approved plan, observer and current clock to reconstruct and compare
complete policy/configuration bytes. It shares the earlier parent budget without
renewal. After authority acceptance, the caller remeasures and rechecks current
facts before returning. T012R/S still own real launch/registration/takeover; typed
records and fixture labels are not claims of deployed authentication or separation.

retain mandatory run/measured-field checks and their signatures. The new template
helpers are not public proof-policy routes. This realizes the existing exact-four-
late-field decision and introduces no new profile, neutral schema or authority.

The internal concrete plan closes configuration_template, policy_template,
measurement_plan, derivation_rules, staging_policy, hosting_selection_digest and
source_hold_ref under the accepted v2 top-level profile. Measurement selects
root-relative paths through protected construction; it exposes no worker resolver.
Real GitHub/Azure/guest/state/issuer clients and their complete request-budget
qualification remain T012Q. This slice does not qualify those provider operations.
