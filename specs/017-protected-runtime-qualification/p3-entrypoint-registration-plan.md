## Concrete placement and contracts

Use the existing original source-controller StageStore on the trusted companion
caller/controller host, with its original expected identity and private owner.
A fixed companion schema v2 adds bounded immutable capture and original handoff
claim slots to the same per-launch row/database. The host store and old v1
controller behavior remain. No side ledger, new backend, nonce initialization,
copy, migration or create-on-open is an allowed materialization path.

The trusted companion caller must have that same original controller-store
capability across the actual phase/process boundary. The proposed proof consumer
runs inside the trusted control/controller ownership boundary; the GitHub runner
is not granted store access. Demonstrate this through the existing phase route,
not only by constructing a same-process fixture. Concrete operator locations
remain T013 inputs under the existing hosting model. A remote-only controller
without that access is explicitly ineligible; no extra lookup or role is invented.

A fixed companion lifecycle wire adds an owner-derived descriptor to the existing
primary register and independent ack-stage replies. Their server origins, principals and server
certificate bindings must be distinct. Reuse the owner's actual
registration and the acknowledgement's existing host/inventory checks; no added
RPC, credential inventory or signing service. Ordinary v1 remains closed and
unchanged. The descriptor binds registration/scope/unit, original lifecycle-store
binding, resource epoch, complete one-to-three credential rows and original time
bounds. Existing handle/owner equality validators remain. Canonical descriptor
limit8192 within the old65536 envelopes; no trimming.

Only owner-module authenticated transport replies can create a sealed capture.
Persist their descriptor and peer/certificate/nonce-digest/reply-digest provenance
in the existing start-consumed transition before host start. No bearer credential or raw
factor material is stored. Durable provenance relies on the original private
controller/store identity boundary; it is not a portable signature or approval.

Before selected handoff I/O, source construction materializes a sealed registration
view locally from that original store. It derives N from every original credential
row and retains both owner and controller store bindings. Atomically consume the
same original launch_ref row's handoff slot, binding scope/plan/source/descriptor/
store/deadline, and return a capability only after known commit. A consumed/lost/
ambiguous attempt cannot be reconstructed. The original independent actual-run
authority and full producer/acceptance seam remain mandatory.

## Implementation sequence after exact source acceptance

First construct genuine original stage fixtures through their actual authenticated
primary and independent exchanges. Create the original selected controller schema
only in the existing staging setup path, once, and retain its identity. Test every
old/new wire/store cross-use before attempting a connected positive.

Then capture and reopen the original descriptor through real process boundaries.
Demonstrate that a caller cannot supply a count, JSON descriptor, future RunPlan,
fixture life/store pointer, copied DB or replacement identity. Verify wrong scope,
source/run/attempt/unit, peer, epoch, registration, store and omitted/duplicate
credentials refuse before selected accounting or handoff. Reopen never initializes.

Exercise original same-row claim commit before authority I/O, races and loss at
capture, store commit, claim and reply boundaries. Exactly one caller may receive
a claim; failed/unconfirmed reservation supplies no capability or retry. Read-only
resolution/cleanup remains separately authorized. Do not turn source-private
one-shot state into a claim of durable cross-process exactly-once behavior.

Repeat Gate A across all six authenticated source consumers and actual preflight/
protected paths. Repeat Gate B using the genuine retained view/claim and existing
exact VerifiedRemote, independent final authority and FinalizationBinding/
FinalizedPlan seam. Reuse original staging launch_ref, scope, generation and actual
lifecycle checks. Keep final RunPlan equality with original resources.

Only after both gates fit, connect unchanged full admission, RuntimeBridge,
Qualifier/report and immutable packaging under the original P08 plan. Measure N1,
N2 and N3, complete callbacks/physical RPCs and local retention work; preserve the
unamended private12 refusal as a regression. Handoff12+2N, cleanup2+5N, audit-only1+N,
staging16, qualification39, GitHub28/protection18, two finalization members and
original clocks/body limits remain bounds. Any mismatch returns to governance.

Finish exact-source full/native identity and fingerprint comparisons, refusal/
crash coverage and fresh independent fixture audit before disposition/cleanup.
Then prepare later source-review/acceptance evidence. A descriptor schema or
passing narrow source controls cannot close the complete P08 requirement.
